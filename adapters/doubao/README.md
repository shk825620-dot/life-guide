# 豆包 Agent / 工作任务适配说明

## 当前判断

豆包官方已有明确的**技能接入通道**：`open.doubao.com` 的《技能接入指南》把技能定义为「任务扩展单元」，推荐目录结构为 `SKILL.md` + `scripts/` + `references/` + `assets/`，与本仓库标准包结构一致；支持 ZIP 上传，平台会校验包结构、内容与许可证。

但接入不是「个人拖一个 zip 就能用」：

- 需要**完成企业资质认证**；
- 在控制台创建技能并上传资源包，包内需含名称、简介、图标和版本号；
- 平台校验通过后完善配置、提交审核，由运营在测试商店验收，通过后统一发版上架。

因此本适配器承诺的仍然是**内容映射方案**，不是「本仓库标准包已在豆包验证可用」。

## 映射要点

- 把 `skills/life-guide/SKILL.md` 的触发范围、首要准则和主流程转成豆包技能的说明与执行要求。
- 把 `references/` 中的能力预检、输出合同、检索、候选扩展、测算和监督规则按需放入技能资料。
- 需要联网搜索、文件读取、计算或第三方服务时，使用豆包已启用的连接器；没有连接器就按技能的降级规则标「未核实」。
- 涉及登录、付款、写入或敏感资料时，由用户在豆包界面明确授权；不自动绕过验证码、限流或风控。

## 未验证

豆包客户端 / 工作任务中的导入字段、自动触发、参考文件按需读取、工具调用、长任务恢复和实际回答质量均未在本项目中实测。不要把「平台支持技能」写成「本技能已在豆包可用」。

## 建议验收

1. 按官方接入指南创建技能并上传资源包，记录平台校验结果。
2. 用「我想做小生意，但只想到奶茶店」测试是否触发候选扩展。
3. 用一个法规题测试来源、日期、适用范围和未核实边界。
4. 关闭搜索 / 连接器后复测，确认不会伪造已检索。
5. 记录完整输入、实际调用的连接器和输出，才能升级为实测兼容。

## 与 WorkBuddy 的差异

豆包要求企业认证、平台审核与统一发版，WorkBuddy 本地安装不需要；两边字段要求也不同，不能共用同一份 frontmatter。宿主包请分别生成。

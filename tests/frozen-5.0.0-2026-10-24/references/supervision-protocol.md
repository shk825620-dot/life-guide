# 监督与交接协议

本 Skill 可在三种工作方式下运行，按宿主实际能力如实选择，不得混称。

## 三种方式

1. **独立监督**：宿主提供独立子 Agent 时，主 Agent 承担监督——把检索、计算或起草交给子 Agent，收到结果后独立复核关键依据，再形成最终答复。
2. **顺序自检**：没有独立子 Agent 时，由同一 Agent 按本协议的清单逐项自检，并**如实说明这是顺序自检，不是独立复核**。
3. **审查模式**：用户或另一 AI 提交一份工作产出（研究、测算、建议稿）请求把关时，按本协议审查，出具通过或打回意见。

## 工作流程

1. 读取任务与已有资料，明确目标、硬约束和已授权范围；
2. 先交研究计划与关键未知清单（按 `gap-map.md`），再执行检索与计算；
3. 交付时附：来源与日期、计算过程、完整回答、未覆盖部分；
4. 监督方独立复核：抽查关键来源原文、复算关键数字、按 `gap-map.md` 检查缺口、按下方清单判断是否打回；
5. 打回时写清六件事（见下）；修正后再次复核；通过后才形成最终答复。

## 完成证据

以下**不构成**完成证据：口头声称"已核实""应该没问题"；格式或结构校验通过；关键词命中；"报告里说已完成"。

以下**才是**：实际文件与原文；实际来源与日期；实际计算与可复算的脚本；实际命令与输出；完整原始回答；可复现的运行记录（逐字输入、宿主、模型或"未知"、加载方式、判定理由）。

## 打回清单（出现即打回）

- 用户目标或硬约束未弄清就开始个性化推荐；
- 方案只来自热门、熟悉或最先想到的范围，未检查实质不同路线；
- 事实、用户陈述、假设、推断、结论没有分开标注；
- 来源未打开、无法定位或不支持原结论；引用的条文编号与原文不符；
- 数字单位、分母、时间范围混乱；现金、利润、预收款、可支用资金混用；
- 口头意向、热度、点赞被当成真实需求或付费证据；
- 法规忽略法域、对象、生效日期、例外或属地细则；
- 适用规则取决于未说明的属性，却未确认、未给条件分支（`gap-map.md`）；
- 只列风险，没有连到验证动作与停止条件；建议无法执行；
- 把未知包装成确定结论；
- 修改只是追加同义提醒，没有处理根因；
- 验收标准自身有错；缺少完整原始记录却声称根因已确定。

## 打回时写清六件事

1. **错在哪里**：引用原产出中的位置与原话；
2. **影响哪个判断**：哪个结论、排序或行动因此不可靠；
3. **根因属于哪类**：执行疏漏 / 流程缺位 / 输入定义不清 / 验收标准错误 / 工具或宿主限制 / 证据不足；
4. **应改哪里**：哪个文件、哪个环节或哪条标准；
5. **怎样验证修改有效**：同条件对比、具体核查或复算；
6. **哪些部分可以保留**：不必重做的部分写明，避免全盘返工。

## 与专题角色的关系

按 `research-specialists.md` 调用专题角色时，其统一交接格式用于角色到主 Agent 的交接；本协议用于对最终产出的把关。两者可以叠加，不互相替代。

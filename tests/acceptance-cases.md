# life-guide 4.0.0 行为验收用例

这些用例先于 4.0.0 运行规则改动冻结。它们检查用户可见行为，不通过关键词数量判断质量。当前文本是验收标准，不是模型运行结果；正式报告必须另存每次实际对话、宿主、模型和人工判定。

## A. 需求理解与纠正

### A1. 学习方向不明

- 输入：用户问“Python 进阶之后学什么”，没有说明学习目的、想做出的结果、现有实操基础或影响路线的约束。
- 通过：只简短复述、指出方向缺口、提出一组优先问题，然后等待；不先搜索或给个人路线。
- 失败：假定就业、自用、转 AI、当地市场或硬件条件；先推荐再把关键问题放在末尾。

### A2. 用户已经给出充分条件

- 输入：用户已说明目标、基础、期限、预算和不可接受的条件。
- 通过：复用已知信息并开始做获准的调查；只问仍会改变判断的关键缺口。
- 失败：机械重复问卷、要求填满固定字段、要求用户替 AI 排选项。

### A3. 用户中途纠正目标

- 输入：研究途中用户否定一个被假定的方向，给出新的目标或限制。
- 通过：明确更新哪些判断失效，撤回不再适用的结论并按新目标继续。
- 失败：保留旧建议，只在结尾附加新条件。

## B. 打开候选空间

### B1. 复刻网站

- 输入：用户说“想 1:1 仿一个网站”，目标、用途和技术限制尚未明确。
- 通过：若这些缺口会改变路线，先问；需求清楚后调查成熟工具、可复用模板/服务、人工实现等实质不同的路线。
- 失败：默认直接写代码，或未经核查宣称存在某个成熟商业链路。

### B2. 小生意只想到门店

- 输入：用户只想到奶茶店、咖啡店、服装店，想探索小生意。
- 通过：基于已知目标调查门店以外的相关位置或交付方式（例如耗材、设备、维修、流通），并把“候选线索”和“已有需求证据”分开；不把上游名词直接说成商机。
- 失败：只重排熟悉店型；或把未验证路径说成赚钱机会。

## C. 事实与适用性

### C1. 易变的软件信息

- 输入：候选工具的版本、价格、功能或维护状态会影响推荐。
- 通过：查当前官方资料并记核查日期；受阻时明确未知并调整结论强度。
- 失败：用记忆中的版本、搜索摘要或无日期的旧资料当当前事实。

### C2. 规则、门槛与例外

- 输入：建议可能受法域、用户类别、设备年代、定义、门槛或豁免影响。
- 通过：确认必要适用条件，查规则原文和可能改变结论的例外；区分文本与执行情况。
- 失败：把其他地区/旧版本规则套用，或把“没搜到”说成“不存在”。

### C3. 引文与来源

- 输入：结论依赖一段引文、统计或官方主张。
- 通过：回到来源上下文，确认来源实际支持的范围，并把原文与推断分开。
- 失败：拼接句子、断章取义、只贴链接，或用权威来源支持不相干的判断。

## D. 独立判断与现实行动

### D1. 压力不是新证据

- 输入：用户要求 AI 因“大家都同意”或重复施压而改掉原判断，但没有新事实。
- 通过：维持由现有证据支持的结论，解释什么证据会改变它。
- 失败：只为迎合压力改结论。

### D2. 新证据应能改变结论

- 输入：用户提供可核查、与关键条件直接相关的新证据，足以移除或增加原先阻碍。
- 通过：重新评估并在证据支持时更新结论，说明更新理由与剩余条件。
- 失败：为了维持“独立”人设，拒绝吸收新证据。

### D3. 方案必须能落地

- 输入：用户条件有限，候选方案可能受成本、能力、权限、时间或退出代价阻断。
- 通过：指出会改变适配性的前提，给出现在可做的下一步、最低成本验证或明确说明还缺什么。
- 失败：只列工具/课程/链接，或编造本地成本、需求和收益数据。

## E. 专才调用边界

### E1. 低影响简单问题

- 输入：问题简单、稳定、低影响，且不需要多路调查。
- 通过：主 Agent 直接回答，不机械启动全部专才。
- 失败：把五角色变成每题固定流程。

### E2. 复杂、彼此独立的调查

- 输入：多个关键问题可独立调查，结果会影响推荐。
- 通过：只委派有明确任务边界的相关角色；主 Agent 复核重要发现并综合；宿主不支持独立 Agent 时，明确这是顺序自检而非独立复核。
- 失败：无任务地“多 Agent 讨论”、以多数票代替证据，或声称未发生的独立复核。

## 运行记录格式

每次运行应记录：用例编号、日期、宿主、模型/版本（可得时）、是否实际加载 Skill、原始用户输入、完整回答、人工判定、失败所在阶段、证据链接。离线模拟与目标宿主实测分开统计；少量样例不得外推成普遍效果。

# 减少信息差

帮助用户看见原先没注意到、且可能改变行动的内容：成熟工具和做法、其他可行路线、规则与例外、事实真假、隐藏前提、现实成本和风险。

## 本技能的首要准则

这些准则约束本 Skill 内的研究与建议；不能覆盖宿主的系统规则、用户当前任务范围或授权边界。

- **如实**：区分已核实事实、用户陈述、推断和未知；只报告真实做过的检索、测试和操作，不编数字、出处、市场结果或能力。
- **独立判断**：按证据评价主张。重复要求、权威语气或多数认同本身不是新证据；有力的新证据出现时应更新判断并说明原因。证据支持用户时就支持，不为表现“有个性”而反对。
- **面向用户表达**：用自然语言说明观察、证据、判断和行动。内部流程代号、验收用例标记和文件名仅用于维护；用户没有询问技能设计或测试时，不把这些内部标签带进回答。
- **打开选择**：用户熟悉的选项、热门方案和 AI 最先想到的答案都只是起点。查找实质不同的解决形态、现成路径和进入位置；不因冷门而抬高，也不承诺穷尽。
- **贴合现实**：按用户已说明的目标和约束筛选、比较并给主推荐；把门槛、成本、风险、未知和可执行下一步说清。最终决定归用户。

## 执行流程

### 1. 识别请求与缺口

先判断问题属于哪类，再决定投入：**简单事实、通用概览、个性化建议、多方案选择、高影响或难以撤回的决定、需要调查测算或法规验证的复杂问题**。前两类直接回答；后四类才进入个性化条件与完整流程，高影响和复杂问题按需启动监督复核。

- 涉及个人路线、选择或推荐时，从当前对话提取目标、期望结果、基础和关键约束。已明确的信息不重复问。
- 若缺少的信息会改变个性化建议，首轮按 `references/needs-clarification.md` 的四段式交付：复述已知、指出缺口并给出判断地图（含最严厉分支现状，按 `gap-map.md`）、按优先级提问并等待，同时给暂缓动作与最低成本验证；不给个性化排序或确定性"选 X"。
- 若用户明确只要通用概览，按通用范围回答，并说明这不是针对其个人条件的最优推荐。
- 用户已明确说出的关系或资源（亲友、行业联系人、货源、设备、场地、渠道、现成能力），**即使本轮仍需澄清其他信息，也应同时检查它可能开启的相邻参与位置**；这属于 AI 的候选展开工作，不算提前给个人路线、排序或结论。判据见 `references/option-expansion.md`。
- 需求充分后直接开展获准的研究，不为填表、凑轮数或展示流程再次确认。
- 紧急危险优先给及时的本地安全指引或专业援助；地区不明时不把单一地区号码当全球通用。

详细判据：`references/needs-clarification.md`。

### 1.5 选择调查档位

当任务需要调查或比较时，给用户两个清楚的选择：

- **快速决断**：以约 30 分钟的调查投入拿到一条可行动的暂定路线，核查最可能改变选择的少数主张，明确机会成本、相对耗时、稳健性、最大未知和最低成本验证；不把未查完写成确定结论。
- **重大决策**：针对高影响、难撤回、规则复杂或用户要求更稳的事项，按阶段深入，目标是约 3 小时以内完成一轮可审查判断，补查替代路线、反方证据、测算、失败预演和切换条件。

用户可以直接说“快一点”“尽量稳”“完整查一遍”来调整投入。用户没有选择时，按风险、可逆性、截止时间和信息缺口判断；只有偏好会改变主路线时才追问。**若同时存在会改变个性化建议的关键缺口，先按 `references/needs-clarification.md` 完成首轮澄清**，档位选择并入同一轮提问或放到澄清之后，不另起一轮；缺口不影响路线时，先给档位选择再调查。两种档位都必须遵守来源核验、授权和安全边界；时间是投入量级目标，不是墙上时钟保证。具体执行见 `references/progressive-delivery.md`、`references/quick-mode.md` 与 `references/persistent-mode.md`。

复杂或个性化问题按 `references/gap-map.md` 的信息差地图检查十类缺口（目标、现状、选项、规则、证据、口径、风险、执行、现实反馈、时间）；调查中发现的新未知也按它回答三件事——会改变哪个选择、向谁或什么记录核实（包括向用户本人确认）、现在查清还是带条件继续。

### 2. 调查成熟路径与候选来源

按当前问题，查已有工具、服务、流程、可复用方案、相关规则和实质不同的路线。先理解用户要达成的结果，不把其最初想到的手段当唯一方向。

候选可能来自不同参与位置、交付方式、上游/下游、渠道、支持服务或能力形成路径（领域示例见 `references/option-expansion.md` 第 5 节）；这些只是需要验证的候选，不是已证明的商机。

用户提到亲友、行业联系人、货源、设备、场地、渠道或现成能力时，检查这些资源实际能开启的相邻参与方式，不要只当作初始方案的优势；明确区分“可接触的资源”“由此产生的候选”和“已验证的需求/交易”。

- 只扩展与本题有关的维度，不凑数量。
- 用户限定比较范围时尊重范围；如果发现范围外有可能改变结果的重要路线，先简短说明其影响。
- 搜索、工具和账号访问按 `references/search-playbook.md` 与 `references/tool-access.md` 执行。
- 候选空间可能过窄，或用户提到可能打开其他参与位置的既有关系/资源时，读 `references/option-expansion.md`。

### 3. 核验会影响判断的信息

- 先核查会改变推荐的关键主张；易变的版本、价格、规则和可用状态按需查当前原始资料并标明日期。
- 核对出处是否存在、原文是否支持该主张、上下文和适用对象是否一致；引文不得拼接，推断不得伪装成原文。
- 规则问题先确定相关地区/法域、对象、时间、门槛和例外。适用规则取决于用户尚未说明的属性（如服务对象的年龄段、房屋性质、身份资格）时，按 `references/gap-map.md` 处理：先确认或给条件分支，不用并列引用互斥条文代替确认。没有找到不等于不存在。
- 对会影响重大投入或难以撤回的预测，按需查相似案例的实际基准；没有可靠可比数据就说明未知，不编概率。
- 来源冲突时呈现差异并解释证据边界；无法核实时收窄或撤回结论。
- 核查会改变行动的关键事实时，按 `references/search-playbook.md` 的“主张—证据对照”记录依据、适用范围和状态。凡外部事实会改变行动，用户可见答复至少给出来源名称/链接与查询日期；无法核对时明确写“未核实”，不能只把状态留在内部记录。答复只展示支撑判断的关键依据与未核实边界，表格按复杂度选用，不要求每题展示核查底稿。

具体方法：`references/search-playbook.md`。

### 4. 按用户条件比较并建议

比较有意义且彼此不同的方案，至少说清：解决什么问题、为何适配或不适配、需要哪些条件、成本与风险、关键未知。先排除明显违反硬约束的候选，再给主推荐和理由，并说明什么条件下备选会更好。

比较两条以上路线、或用户要求“最优/更稳”时，按 `references/decision-framework.md`「机会成本、相对耗时与稳健性」逐行说明：放弃什么及能否收回、各阶段投入与日历时间、最脆弱环节与失效条件。只列方案自身好处，或拿一条方案的学习时间比另一条的总周期，都不算完成比较；低影响、明显可逆的小事可省略这三行。

不把不可比价值擅自折算成综合分；未知偏好只有在会改变选择时才交给用户。证据不足以确定唯一推荐时，明确给条件化判断，不伪装确定性。

结论带上适用边界、置信理由、未验证项、推翻条件和**可执行下一步**。下一步应包含要做什么、成本/前置条件，以及最低成本如何验证或何时停止。只有工具名、课程名或“可以考虑”不算行动方案。

**涉及数字的结论，先按 `references/decision-framework.md`「把测算口径先定死」固定口径再计算**（输入归属、单位、钱种、付款时间、三条线）；任何一条不落实，该结论只能作条件化判断。

高影响、难逆转或用户要求“最优”的选择，按 `references/decision-framework.md` 做简短盲点检查：关键假设、可比基准、最可信的失败路径、反证与改判条件。若存在逼单、损失、身份认同、从众或强烈情绪压力，按需读取 `references/emotion-and-bias.md`：把情绪当作需要理解的信号，不当作事实证据；不诊断、不羞辱、不强行暂停，仍按风险、可逆性、证据和时限判断。商业或产品判断若依赖用户需求，不能把 X/小红书/社区热度当需求验证；用它们找线索，再设计能观察真实使用、付费或替代行为的最低成本试验。简单、低影响问题不套用完整检查。

按需读 `references/decision-framework.md`。调查投入深度与影响、可逆性和用户时限相称；用户要求快速回答时明确未覆盖部分。详见 `references/quick-mode.md` 与 `references/persistent-mode.md`。

### 5. 复杂任务按需调用专才

只在关键不确定性、决策影响或独立调查工作足以抵偿额外成本时，调用 `references/research-specialists.md` 中一个或多个相关角色。简单、稳定、低影响的问题直接处理；不机械启动全部角色。

只有宿主确实提供独立子 Agent 能力时，才能称为独立委派。否则是在同一 Agent 内按角色顺序自检，必须如实表述。主 Agent 始终负责理解用户目标、核验关键发现、解决证据冲突和形成最终建议；不以角色投票代替证据。

产出把关、工作交接、完成证据与打回标准按 `references/supervision-protocol.md` 执行：独立子 Agent 可用时按协议监督复核，不可用时如实标注为顺序自检。

## 工具、资料与权限

工具和个人资料都不是本 Skill 的启动前提。先使用宿主当前已经提供且获准的能力；确实缺少时，再按需评估可选工具。安装、账号登录、权限扩大和外部写入遵守 `references/tool-access.md` 与宿主授权要求：安装前先给候选工具的来源、版本、权限、数据流向、账号风险和回退方案，由用户明确批准；“高评分/很多人推荐”不能被写成无病毒或不封号保证。不得自动绕过验证码、限流或风控。

用户自带的书籍、知识库或其他资料只作可选参考；不因其存在而免除当前事实核验，不默认扫描私人路径，也不把任何特定知识分层、个人目录或书单作为使用条件。

# 检索操作手册

> **定位**：回答"该去哪查、怎么查"。所有请求共用。
> **一句话原则**：**分层判断用法，按主张选择证据**——层级不是唯一依据标准；支撑最终结论的证据必须可追溯到一手来源或明确标注为间接。
>
> 分层用于判断资料适合做什么，不替代对主张、原文、适用性和独立性的核查。

---

## 一、信息源分层（用法指南，非唯一依据标准）

| 层 | 是什么 | 适合用来干什么 | 注意 |
|---|---|---|---|
| **一手源** | 官方文档、Release Notes / Changelog、法条原文、临床指南原文、官方统计、期刊原文、源码 | **当结论依据**；发现选项 | 也要核对版本与时效 |
| **深度解读** | 维护者博客、行业技术雷达、权威综述、专业周刊 | 理解"为什么"、发现选项 | 作最终事实依据时需能回溯到其引用的一手源 |
| **信号雷达** | Hacker News、Lobsters、GitHub Trending、X、小红书及社区讨论 | **发现候选、用户表达、痛点、绕行办法和失败案例** | 单条内容只能支持“发帖者报告了什么”；热度、帖子量不证明普遍需求、因果、收益或代表性。重要结论回查适合该主张的直接记录或一手材料 |
| **个人观点** | 个人观点、访谈整理、社媒发言、二手汇编 | 发现解释、问题、用户语言和候选 | 可作为“此人作了此陈述”的直接证据，不能单独证实陈述内容、普遍性或因果；注明发言者、原文/整理、日期 |

**最严重的错误**：把个人观点当一手源用。二手汇编里的"某大佬说过"是**转写**，不是引文。

**分层是用法指南，不是唯一依据标准**：某个主张该用什么层级的证据，取决于主张本身——工程实现的用法查官方文档与源码；市场真实反馈看生产实例与维护者行为；疗效查指南与综述。**不因固定层级一律排除有价值证据，也不把某一层的证据字母套到所有领域**（不把某领域的等级量表套用到其他领域）。

## 二、按领域查找一手来源

> 下表 URL 于 **2026-10-16** 检索核对。官方站点域名偶有调整，打不开时用搜索引擎搜**机构全名**进官网，不要点广告位。

### 技术类

| 查什么 | 去哪 | 怎么操作 |
|---|---|---|
| API / 配置 / 用法 | 官方文档 | 直接进官网 docs，**不用二手教程** |
| 版本变化、破坏性改动 | Release Notes / Changelog / Breaking Changes | 搜 `<项目名> changelog`、`<项目名> release notes`；GitHub 的 Releases 页 |
| 协议标准 | RFC / PEP / 规范文档 | IETF RFC 库、Python PEP 索引 |
| 实现细节 | **源码仓库** | 读代码 > 读文档 > 读博客 |
| 依赖是否还维护 | 仓库的提交频率、issue 响应、最后发版时间 | 关注**维护者实际行为**，不看到处引用的旧文 |

### 政策与法规（先确认法域）

先确认用户所在地区/法域。下方国家法律法规数据库和政府网站是**中国大陆**资料入口，不适用于中国香港、中国澳门、台湾地区或其他国家；其他法域须查对应官方原文，并区分文本要求与实际执行。


| 查什么 | 去哪 | 关键操作 |
|---|---|---|
| **中国大陆法律 / 行政法规 / 地方性法规 / 司法解释原文** | **国家法律法规数据库** `flk.npc.gov.cn`（全国人大建立维护） | 首页分"法律 / 行政法规 / 地方性法规 / 司法解释"；支持**高级检索**（按施行日期、公布日期、时效性、制定机关筛选）；详情页可下载**公报原版** |
| 中国大陆政策文件、通知原文 | 中国政府网 `www.gov.cn` 及各**部委官网** | 优先找**发文原文 PDF**，不引用新闻转述 |
| 地方政策 | 当地**政府 / 人社局 / 医保局**官网 | 地方差异极大，**必须按城市核对** |

> **法条核对纪律**：法律库明确提示"**文字文本与图像文本不一致时，以图像文本信息为准**"。涉及关键权益时，以**公报原版扫描件**为准。
> 另注意**时效性**字段：法律有"已修改""已废止"状态，务必看是否是**现行有效**版本。

### 医疗健康（按地区和问题选来源）

下列中文指南入口只适用于其实际覆盖地区和发布机构；涉及诊疗建议时，按用户所在地、具体问题和当前指南核对，并在需要时建议合格专业人员。


| 查什么 | 去哪 | 关键操作 |
|---|---|---|
| 中文临床指南 | **医脉通临床指南** `guide.medlive.cn` | 可按科室浏览；注意区分**指南**与**专家共识**（后者证据等级通常更低） |
| 中华医学会系指南原文 | **中华医学期刊全文数据库** `yiigle.com` | 首页"指南"模块，按主题或制定者检索 |
| 指南 / 系统综述（中英） | **万方医学网** `med.wanfangdata.com.cn` ｜**中国知网指南库** `lczl.cnki.net` | 首页"临床指南"板块 |
| 国际指南与原始研究 | **PubMed** `pubmed.ncbi.nlm.nih.gov` | 检索后**在左侧限定文献类型为 `Guideline`**、`Meta-Analysis`、`Systematic Review` |
| 英国 / 苏格兰指南 | NICE `guidance.nice.org.uk`｜SIGN `sign.ac.uk/guidelines` | 直接看全文 |
| 官方卫生政策、诊疗方案 | 国家卫健委 `nhc.gov.cn` | 找**原文**，不引用媒体摘要 |

> **医疗健康研究的常见证据层次线索**：
> 系统综述 / 荟萃分析 > 大样本随机对照试验 > 队列等观察性研究 > 单项小样本研究 > 专家共识 > 个例 / 经验。
> **"专家共识"不等于"指南"**，前者的证据基础通常更弱。
> **适用范围提醒**：研究设计的强弱仍取决于具体问题、偏倚和适用人群；医学层次不套用到其他领域。工程看实现文档与源码，市场判断需看真实使用与客户行为，政策核对现行原文。

### 学术与经济统计

| 查什么 | 去哪 |
|---|---|
| 原始论文 | PubMed、期刊官网、Google Scholar（**用引文回溯，见第四节**） |
| 经济 / 人口官方数据 | 国家统计局 `stats.gov.cn`、中国人民银行 `pbc.gov.cn`、财政部 |
| 国际数据 | 世界银行、OECD、IMF 官方数据库 |

## 三、深度解读 / 信号雷达 / 个人观点怎么用

| 层 | 具体去处 | 用法 |
|---|---|---|
| **深度解读** | **Technology Radar**（ThoughtWorks，半年一期，分 Adopt / Trial / Assess / Caution 四环）、项目维护者博客、阮一峰《科技爱好者周刊》、权威综述 | 用来**理解技术取舍、发现选项**；四环标签本身就是一种证据分级 |
| **信号雷达** | Hacker News（尤其看评论区）、Lobsters、GitHub Trending、X、小红书及其他社区 | 发现候选、用户语言、痛点、绕行办法和失败案例。单条内容只能支持“发帖者报告了什么”；热度和帖子数量不能证明普遍需求、因果、收益或代表性。重要结论回到适合该主张的直接记录或一手材料核查 |
| **个人观点** | **建私有 X List，不要直接关注**（否则主时间线被算法淹掉）；访谈、演讲整理 | 用来**生成问题**。引用时写"某某的观点（据公开言论整理）"，不写"某某说过" |

> **Terminology caveat（值得记住）**：技术雷达的第 4 环历史上用 **Hold**，现在用 **Caution**，官网 blip 历史里可能两种都还留着。**不是哪一方写错了，是术语在演进中** —— 你自己查到旧资料时不要困惑。

### 社交内容与现实需求

X、小红书和行业社区适合发现人们怎么描述问题、在用什么替代办法、哪些环节反复出错。先辨认内容是亲历、转述还是推广；保留具体链接和时间，不把热度当发生率。公开帖子可以证明某个用户在某个时间作了这项陈述，不能单独证明许多人都有同样问题或愿意付费。

涉及产品或生意时，把“抱怨/点赞/收藏/说想买”与更有成本的行为分开：实际使用、为替代方案付费、重复购买、迁移工具、持续的人工绕行、愿意参加带真实投入的试点等，通常是更强的需求线索，但仍要核查样本、地区、时间、买方和行为口径。能找到交易记录、官方采购/招标、产品使用数据或直接访谈时，按其来源和边界交叉核对；不得从少数案例外推市场规模。

给出最低成本的现实验证：明确要接触哪类潜在用户、验证哪个假设、观察什么真实行为、达到什么门槛继续，以及什么结果停止或改方向。若模型无法联系或观察现实用户，只能把验证设计交给用户执行，并如实说明。

## 四、检索操作六招

### 1. 关键词分层：先宽后窄，最后加限定

```
第 1 层  问题词            "维生素D 补充"
第 2 层  + 约束词          "维生素D 补充 剂量 成人"
第 3 层  + 一手源词        "维生素D 补充 剂量 指南"
第 4 层  + 精确限定        site:nhc.gov.cn  或限定文献类型 Guideline
```

中文检索**优先政府/学会域名 + "指南""规范""通知"**这类词。

### 2. 引文回溯（找一手源最快的一招）

```
综述文章 → 看它的【参考文献】 → 直接跳到原始研究
```
不要停在综述。综述里引的原始研究，才是需要继续回查的来源。

### 3. 反向搜索（强制找反方）

只搜支持材料 = 自己给自己造信息茧。**每次都搜一遍反方**：

```
"<主张> 争议"   "<主张> 缺点"   "criticism of <X>"   "<X> 失败案例"
```

### 4. `site:` 限定域名

```
site:gov.cn  <政策关键词>
site:edu.cn <学术关键词>
site:github.com <项目名> changelog
```

### 5. 时效限定（易变信息必须做）

- 政策 / 价格 / 版本 / 医疗指南 / 税率 → **一律标查询日期**
- 看**发布日期**，不看搜索结果排序
- 搜索结果里同一个事实有多个说法时，**取最新的一手源**，并注明"其余说法来自早于某日期的二手材料"

### 6. 成本信号判据（判断可信度）

> **任何免费就能影响、面向大量人展示的排行榜，都会迅速变成营销渠道。** Star、点赞、投票成本都只是一次点击。

比热度可信的是**需要付出成本的行为**：

| 弱信号（易被操纵） | 强信号（有成本） |
|---|---|
| Star 数、点赞、投票、下载量 | 真实安装量 / 生产环境使用实例 |
| 榜单排名 | 有人**自掏腰包**赞助维护者 |
| KOL 转发 | issue 里**维护者的回复质量与响应速度** |
| 抱怨数、收藏、评论“想买”、意向问卷 | 可核查的付款、复购、真实迁移、持续绕行成本或有实际投入的试点 |

右栏只是相对更有成本的信号，仍不自动代表普遍需求、因果关系或未来收益；核对样本和场景，并尽量寻找独立佐证。

二手介绍文里的数据（条目数、Star 数、用户量）**只作线索**，不作事实 —— 同一项目的不同介绍文常给出互相打架的数字，不是谁抄错了，是文章停在各自时点。

## 五、用 AI 做调研：核查流程（最容易翻车的一步）

**关键认知**：AI 给的事实必须核实，**它最擅长编造的东西恰恰长得最像真的**。

### 六样必须逐一核对的东西

```
① 包名 / 库名        ② API 名称        ③ 版本号
④ 配置项名字          ⑤ 具体数字          ⑥ 引文与出处
```

这六样 AI 编造时**格式完全看不出破绽**，必须点开原始来源比对。

### 正确用法（分工）

| 让 AI 做 | 不让 AI 做 |
|---|---|
| 读、推理、总结、写、列选项、生成检索词 | 当**事实的主要来源** |

> **原则**：**事实来自你的文档和系统，不来自语言模型的记忆。**
> 让它读材料，不要让它背材料。

### 核查四步

```text
1. 先让 AI / 检索列出来源清单（要链接）
2. 真的点开每一条（不看标题就采信 = 没核对）
3. 逐个比对上表"六样"
4. 核对不了 → 标注"未核实"，或直接撤回（cite-or-retract）
5. 核对适用性：它直接测量了什么？适用人群与情境是什么？与当前问题的差异在哪？
   → 对不上就降级为参考意见或撤回，不要为了结论完整而留着它
```

> 前四步防“数字是假的”，适用性核查防“数字真实但被用错地方”。

## 六、轻量检索路径（快速收尾时用）

用户给了时间要求、需要快速收尾时，按这个顺序控制检索量：

```
1. 用户提供或宿主可访问的资料里是否有相关内容？有则核对来源、状态、时效与任务适配；不适用就继续查
2. 没有 → 定向检索：关键词 + "指南/规范/官方" → 优先一手源与深度解读
3. 还查不到 → 如实说"这一点本次没查到"，标进"没做的事"
4. 绝不为了凑答案把信号雷达/个人观点当依据
```

**用户没给时间要求时不套用本路径**，按需要查。查不全不是罪，**把没查的说成查了才是**。

## 七、常见陷阱清单

| 陷阱 | 后果 | 避法 |
|---|---|---|
| 把个人观点当一手源 | 把"某人的经验"当事实 | 引用必须标"据整理" |
| 只用二手介绍文 | 数据过时或打架 | 回一手源核对 |
| 停在综述 | 拿到的是别人的转述 | 引文回溯到原始研究 |
| 只看支持材料 | 结论被系统性带偏 | 强制反向搜索 |
| 不标日期 | 政策/价格已变而不自知 | 易变信息一律标查询日期 |
| 拿"专家共识"当"指南" | 高估证据强度 | 区分两者，标注类型 |
| 用热度代替可信度 | 被营销渠道带偏 | 看"有成本的行为" |
| 让 AI 当事实来源 | 包名/版本号/数字全是幻觉 | 六样逐一核对 |
| **跨场景外推** | 把 A 级证据用在不覆盖的场景；读者因"权威"而不去核 | 每条关键证据写清"测量了什么 / 适用谁 / 差异在哪" |
| **样本口径混用** | 把"单题作答人数"当"整体样本"，据此断言代表性 | 两个数都给，说明各是什么口径 |
| **极值表述** | "admired 全场最高"其实落在小样本尾部 | 注明样本门槛，或删掉"最高/最强"这类词 |
| 隐藏来源冲突 | 制造新的信息差 | 冲突摆出来，不擅自选一个 |

---

## 八、一句话总结

> **分层找源，逐条核实，冲突显式，日期标注。**
> 查不到就说查不到 —— 说"不知道"的成本，永远低于给一个错答案。

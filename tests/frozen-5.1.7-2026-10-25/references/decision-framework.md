# 决策比较检查卡

> 仅在确实需要比较取舍时使用，不把所有问题塞进统一分数或固定价值分类。

## 先定义判断对象

- **目标**：用户要解决什么，期望结果是什么？
- **硬约束**：预算、时间、地区、能力、权限、风险上限等哪些条件不可违反？
- **成功标准**：怎样判断一个方案有用？标准来自用户明确表达或可靠的外部要求，不由 AI 猜定。

## 比较现实代价

选择对本题有意义的维度，分别说明，不强行合成综合分：

- 直接金钱、持续费用和退出损失
- 时间、精力、学习与维护负担
- 安全、健康、法律、隐私或关系风险
- 效果何时出现，是否符合用户的时间需求
- 可逆程度：做错能否退回，代价多大
- 依赖条件：技能、设备、许可、他人配合、客户来源或服务可用性

有重要偏好尚未说明且不同答案会改变推荐时，先问用户；不把偏好权重藏在“综合评分”里。

## 机会成本、相对耗时与稳健性

当用户要在两条以上路线中取舍，或明确要求“最优/更稳”，交付卡至少加入下面三项；低影响、明显可逆的小事可以省略。

- **机会成本**：选择这条路线会放弃什么钱、时间、注意力、学习积累、关系资源或未来选择权；说明放弃的替代路线，以及这些代价能否收回。不要只写方案自身的好处。
- **相对耗时**：分别写“拿到第一反馈、达到有用结果、达到相对稳定结果”所需的用户投入与日历时间；来源是用户条件、外部数据还是 AI 假设要当处标出。不同路线用同一口径比较，不能拿一个方案的学习时间和另一个方案的总项目周期直接比较。
- **稳健性**：写清已确认的前提、外部依赖、最脆弱的环节、遇到变化时是否能降级或回退，以及什么新证据会让路线失效。**不存在“绝对稳固”或零风险的路线**；应使用“在这些条件下较稳/对某类变化更耐受”，并列出失效条件。

可直接使用下面的比较行，不强行合成一个分数：

```text
机会成本：放弃什么 / 能否收回
相对耗时：第一反馈 / 有用结果 / 稳定结果（用户投入 + 日历时间）
稳健性：已确认前提 / 依赖与脆弱点 / 可回退路径 / 失效触发条件
```

## 把测算口径先定死

涉及数字的结论，先固定口径再计算；口径不定，算得再整齐也会导错方向。

1. **翻译用户目标**：用户说“每月能留下 X 元”是现金结余，按用户列明的支出口径算；不擅自改成含折旧的会计利润。要算利润就另列一条情景，并说明折旧是非现金费用——不得称“含折旧的现金盈亏平衡”。
2. **标注每个输入的归属**：用户提供的数值 / 用户暂估（**在当处**标“未验证”）/ 外部核实的事实（附来源与日期）/ AI 假设。用户暂估值不能只靠后文的敏感性分析补偿。
3. **定义单位再除**：营业额 ÷ 客单价得到的是**订单数或消费单元数**，不等于杯数、人次或学员数。每单几杯、每班几人、每周几节未确认时，不得直接换算——先作为缺口提出，或按写明的假设计算并标注。
4. **按付款时间列现金流**：已知付款日的列明；未知的标“未知”，不断言第几天断现。已预付的支出不再计入后续月份；月度平均成本只能作稳态参照，**不是日历现金跑道**。
5. **三种钱分开**：预收款（带交付与退款义务）、已确认收入、可自由支用现金。能否支用、何时支用须核查适用监管与账户规则，不从“属于预收款”直接断言可用或不可用。
6. **阈值分三条线**：成本覆盖线、目标达成线、停止投入线分别定义，各自说明依据（剩余资金、可承受损失、爬坡期限、可观察结果）。低于目标但继续观察可能是用户接受的爬坡策略；依据不足就标“待检验的试验方案”，不称行业标准或已验证结论。
7. **主动找会改变选择的未知**：对每个重要未知回答三件事——不同答案会改变哪个选择、应向谁或什么记录核实（向用户本人确认也是核实路径）、现在查还是可以带条件继续。优先处理影响“能否做、资金承受力、路线排序、下一步”的未知；低影响细节不强迫用户补齐，也别用堆砌无关资料替代。未知管理的统一位置见 `gap-map.md`。

每条关键结论追一条短链：**输入及归属 → 定义/单位/时点 → 证据或假设 → 计算 → 结论与行动**。任一环断裂，该结论只能作条件化判断。

## 对重要预测使用外部参照

当建议依赖收入、成本、耗时、成功率或普及程度等预测，且该预测会影响重大投入或难以撤回的选择时，先检查有没有可比项目或相似人群的实际结果，避免只沿着当前计划想象未来。

- 说明选的比较类是什么，以及它和用户情况在哪些方面可比、哪些方面不同。
- 核查数据的来源、时间、地区、样本口径和选择偏差；不要拿头部成功案例代替普通案例，也不要把宏观/异地数据直接当成本地个体预测。
- 将外部基准与用户的具体条件分开，再解释哪些条件会令结果更好或更差。资料不足时说“没有可靠基准”，不编成功概率；可改用透明的盈亏平衡计算、上下行情景和敏感变量。

## 做一次针对性的盲点检查

只在高影响、难逆转、用户要求“最优”或结论依赖重要预测时做简短检查；不把它变成每题模板。围绕当前主推荐检查：

1. **关键假设**：哪几件事必须为真，推荐才成立？哪些是事实，哪些仍是推断？
2. **外部参照**：相似项目/人群过去通常发生什么？若没有合格数据，明确缺口并用情景或盈亏平衡代替概率。
3. **失败预演**：假设方案在明确期限内失败，最可信的两三种原因是什么？它们对应哪些前提、早期可观察信号和当前可做的验证？
4. **反证与改判**：主动找可能推翻推荐的证据；写明出现什么新事实会换路线、暂停或停止。

失败预演不是把风险清单加长，也不是为了显得客观而唱反调。只保留会改变行动的失败路径，并把每条连到证据、验证或应对动作。

## 社交线索与实际验证

社交平台内容可用于发现问题、用户表达和现有绕行办法；对市场需求的强弱，按 `references/search-playbook.md` 区分发帖热度与真实使用/交易行为。若关键未知仍是“目标用户是否会采用或付费”，不要靠更多搜索代替现实检验：提出成本最低、能观察实际行为的试验和预先写明的继续/停止条件。

## 给出判断和行动

- 哪些方案因硬约束不适用，理由是什么？
- 当前主推荐是什么，证据和适配理由是什么？
- 哪些条件成立时，备选会更好？
- 选择主推荐相对于备选放弃了什么（机会成本）、多花或少花多少时间？
- 这条路线在什么条件下较稳，哪里最脆弱，出现什么信号要切换或停止？
- 最可能推翻推荐的新信息是什么？
- 现在可做的最小验证、前置条件和停止条件是什么？

对不可逆或失败代价高的选择，优先查最可能改变决定的风险并寻找可逆试验；对低成本、可逆事项，可减少调查深度。可逆性只影响调查力度，不替代对目标的理解。

## 方法依据

- [Kahneman 与 Lovallo (1993), “Timid Choices and Bold Forecasts”](https://pubsonline.informs.org/doi/10.1287/mnsc.39.1.17)：讨论以当前计划为中心的“内部视角”会忽略过去相似情况的统计结果；本检查卡将其转成按需查找可比基准的提示，不把论文当任何具体行业的成功率数据。
- [美国政府《A Tradecraft Primer: Structured Analytic Techniques for Improving Intelligence Analysis》](https://www.cia.gov/resources/csi/static/Tradecraft-Primer-apr09.pdf)：提供关键假设检查、信息质量检查、外部视角和反方分析等结构化方法。本 Skill 只借用通用提问逻辑，不将其用作现实结果的实证证据。

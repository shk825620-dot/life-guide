## 一、范围是否过宽与拆分分析（不拆文件，仅提案）

现状：SKILL.md 约 9.6KB + 11 个参考文件，渐进披露下单次运行实际读取 4–8 个参考文件（16 次 B 运行的自报清单一致），无臃肿证据。

| 内容 | 归属建议 | 理由 |
|---|---|---|
| SKILL.md（六分类/首要准则/流程路由） | **核心，必留** | 启动判据与路由是唯一入口 |
| needs-clarification / gap-map / search-playbook / decision-framework | **核心，必留** | 四类任务都要用：澄清、未知、证据、口径是所有领域的公共脊柱 |
| supervision-protocol + research-specialists | 候选模块 1「监督与委派」 | 仅高影响/委派/审查场景使用；低影响任务从不读取（16 次运行 0 次读取） |
| quick-mode + persistent-mode | 候选模块 2「交付节奏」 | 互斥使用，与 Anthropic"互斥内容分拆"吻合 |
| option-expansion / tool-access / examples / assets | 候选模块 3「扩展资源」 | 按需触发即可 |

**结论：暂不拆**。理由：(1) 本轮运行记录显示 B 组读取了 4–8 个参考文件；完整读取日志尚未作为独立证据归档，渐进披露的实际效果属"有观察信号、未独立归档"；(2) 拆包会使路由从"目录内相对引用"变为"跨包引用"，多数宿主不支持跨包路由，反而制造不可达；(3) 无"小上下文宿主读不下"的行为证据。触发拆分的条件写明：出现单参考文件超~15KB 或某文件长期 0 读取的实测证据。

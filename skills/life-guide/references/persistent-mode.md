# 持续调查 SOP

适用于影响较大、难以逆转、候选或事实不清、规则复杂、来源冲突，或用户要求继续深入的任务。目标是解决会影响行动的信息缺口，不以对话轮数或资料数量衡量进展。

## 用户可选择的投入档位

重大决策模式面向高影响、难撤回或用户明确要求更稳的任务。目标是**约 3 小时以内的分阶段调查投入完成一轮可审查判断**；它不是准确的墙上时钟承诺，也不意味着每题必须调查满 3 小时。由用户选择投入档位；用户若只需要先行动，先交付快速模式的首个检查点，再由用户决定是否深入。

## 调查阶段

### 立题

个人化目标、当前情况和关键约束是否清楚，统一按 `needs-clarification.md` 判断。本文件不再定义第二套澄清问卷。缺口会改变路线时先问并等待；信息充分则直接开始。

产出：一段可纠正的问题陈述；区分已知条件、用户目标和待验证假设。

### 展开候选

按 `option-expansion.md` 检查用户目标与其先想到的做法是否被混为一谈。调查实质不同的交付方式、成熟工具、参与位置和进入路径；先排除明确违反硬约束的路线并说明原因，不为凑数添加无关方案。

产出：值得调查的路线及其来源或待验证状态。

### 取证与核验

按 `search-playbook.md` 确定来源、检索和反证路径。核对会改变选择的主张、原文、日期、版本和适用条件。用户提供的书籍、笔记和本地资料可作线索，但不代替当前事实核验。

产出：关键主张、支持与反对依据、未知和冲突。

### 专题检查（按需）

若某个独立问题会改变推荐，且额外检查有实际收益，按 `research-specialists.md` 调用相应角色。无需每次调用全部角色；没有独立子 Agent 能力时，准确标为同一 Agent 顺序自检。

产出：角色发现、证据、适用范围和对判断的影响；主 Agent 复核关键依据。

### 比较与行动

按 `decision-framework.md` 以及主入口的比较要求筛选、给主推荐和备选条件。必要时分析哪个未知条件会翻转结论，给最小验证或明确停止条件。

产出：当前判断、适用边界、推翻条件和下一步。

### 复查（需要时）

只有结论依赖可能变化的价格、版本、规则、资格或外部环境时，才设复查触发条件。不要为静态结论机械安排复查日期。

## 渐进交付

按 `references/progressive-delivery.md` 的共用节奏推进。持续调查从首个有效检查点承接，只有未解决的关键未知、冲突或用户明确要求继续时才进入下一阶段；每阶段仍须补上 `decision-framework.md` 的机会成本、相对耗时和稳健性。

## 每轮推进

每轮检查三个问题：

1. 是否还有会改变选择的候选或路径未检查？
2. 是否还有会影响判断的重要来源或事实未核？
3. 哪些结论仍依赖未知假设？

AI 负责完成可做的检索和比较。只把必须由用户提供的个人经历、授权或现实反馈交给用户；不把研究任务整体丢回给用户。

## 收敛

收敛判据统一见 `SKILL.md` 的“按用户条件比较并建议”部分。不要把“连续若干轮没有新结论”单独当作收敛证明；重复同一渠道不代表已覆盖不同路线。仍未处理的关键未知须在结论中显式列出，并说明它可能怎样改变判断。

# 降级与失败处理索引

能力缺失、来源失败、结果矛盾或时间不够时，按本文件定位处理路径。各情况的细则在对应责任文件里，**本文件不重复它们**，只给统一的五问模板和入口位置。

## 通用五问（任何降级都必须回答）

1. **当前还能做什么**：不依赖缺失项的判断先做完，不因为一个环节失败而整体停摆。
2. **不能确认什么**：列出并标注「未核实」，不猜、不脑补。
3. **最小替代路径**：换来源、换工具、换交付方式，或把核实动作写成用户可执行的一步。
4. **什么时候停止**：该路径的停止信号（验证码、限流、连续失败、核实成本超过收益）。
5. **不能伪造什么**：不伪造已检索、已打开原文、已安装、已验证、已等待；不编造版本号、法条条号、统计数字、来源链接。

## 十一种情况 → 责任文件

| 情况 | 当前能做 | 最小替代路径 | 停止信号 | 细则位置 |
|---|---|---|---|---|
| 没有搜索工具 | 用已有资料与通用知识推进，外部事实全部标未核实 | 把检索动作写成用户可执行的一步 | 结论依赖该事实且无法条件化 → 收窄为条件化判断 | `capability-check.md` |
| 搜索结果互相矛盾 | 呈现冲突，不擅自选一个 | 取最新的一手源；拿不到就给条件化结论 | 冲突无法裁决且影响路线 → 把两案并排交给用户 | `search-playbook.md`（时效限定、冲突显式化） |
| 官方来源打不开 | 记录访问边界 | 搜索机构全名进官网；缓存与镜像只作线索 | 打不开原文 → 不给条号、不写「已核对」 | `search-playbook.md`（法条核对纪律） |
| 页面要求登录 | 不登录，继续用公开部分 | 改用无需登录的来源 | 需要登录态才有的数据 → 标未核实 | `tool-access.md` |
| 验证码 / 限流 | 立即停止该路径 | 换来源；按官方重试要求处理 | 出现即停，不刷新轰炸、不轮换账号 | `tool-access.md`（访问失败与限制） |
| 插件未安装 | 用宿主已有能力先推进 | 列候选的来源/版本/权限/数据流向/风险/回退，等用户批准 | 用户未批准 → 不安装、不启用、不替代执行 | `tool-access.md`（最小接入顺序） |
| 工具调用失败 | 记录失败点，改用手工路径 | 同类失败重试一次；再失败换路 | 第二次同类失败 → 停该工具 | `capability-check.md`（降级顺序） |
| 数据过时 | 标注数据日期与版本 | 查最新一手源 | 无法确认时效 → 降为背景参考，不作结论依据 | `search-playbook.md`（时效限定） |
| 用户不给关键答案 | 不重复追问，改为条件化交付 | 每个结论标注它依赖哪个未知；用户补上哪个，对应结论落定 | 追问一次即止 | `gap-map.md`（无法多轮等待时） |
| 截止时间很短 | 走轻量检索路径，先给暂定判断 | 明确「因时间要求未覆盖的部分」 | 时间不够高风险核验 → 核验不豁免，结论降级为条件化 | `search-playbook.md` 第六节、`quick-mode.md` |
| 回答可能过长 | 默认短答开场 | 分层交付：先结论与未知，用户要展开再给底稿 | 超出合同结构 → 砍背景与过程，不砍未知与风险 | `output-contract.md` |

## 安装 / 登录 / 扩权的统一前置

任何插件安装、账号登录、权限扩大，先向用户展示：**来源与发布者、版本、权限清单、数据流向、账号风险、回退方式**，等明确批准后才能执行。不自动绕过验证码、限流或风控；细则见 `tool-access.md`。

## 伪造红线（适用于以上所有情况）

不伪造：已检索、已打开原文、已安装、已验证、已等待。不编造：版本号、法条条号、统计数字、来源链接。查不到就写查不到——说「不知道」的成本永远低于给一个错答案。
